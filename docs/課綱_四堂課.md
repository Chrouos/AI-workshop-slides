# AI 協作工作坊課綱：用 AI 建一座三國知識庫

四堂課，每堂 2 小時（含練習），共 8 小時。

整個課程只做一件作品：一座《三國演義》知識庫。第一堂用 Codex 寫出大綱，第二堂放進 Obsidian 和人物卡連起來，第三堂用 Skill 擴充、畫圖、排時間軸，第四堂發布成網站。每堂課都接著上一堂的成果做。

三條主線貫穿四堂課：

| 主線 | 第一堂 | 第二堂 | 第三堂 | 第四堂 |
| --- | --- | --- | --- | --- |
| RAG | 概念：Web Search 就是 RAG | 實作：在自己的筆記庫查資料、附出處 | 應用：照原文新增卡片 | 成果：網站上每張卡都有出處 |
| Obsidian | （預告） | 安裝、連結、關係圖 | 卡片模板、時間欄位 | Digital Garden 發布 |
| Skills | （預告：AGENTS.md） | （預告） | 安裝、使用、自己寫一個 | 把 Skill 產出放上網站 |

### 10–40　GPT 怎麼走到今天

用一條因果鏈講，每一步都是上一步的問題催生出來的：

1. **預測下一個字（2022，GPT-3.5）**：看前文，從機率表挑下一個字，一直接下去。
2. **隨機性**：每次不一定挑機率最高的那個字，所以同一題問兩次，答案會不一樣。現場示範：同一題按兩次「重新產生」。
3. **幻覺**：它挑的是「最常見的說法」，不是「查證過的說法」，所以會很肯定地講出沒有根據的內容。例子：早期 GPT-3.5 把一長串加法算成 8402（正解 8484）。
4. **解法一：Thinking（CoT，思考鏈）**：先把問題拆成步驟，一步一步算，最後再驗算。這比較少推理錯誤，但本質上還是在「心算」，靠模型自己記得的東西。
5. **解法二：使用工具（像按計算機）**：遇到算術，模型在背後寫一行程式來算，就像把數字輸入計算機、按下等於。這樣得到的是真的算出來的結果，每次都一樣，不再是隨機猜的。實測：請 Codex「用程式算出來」，它執行 `python3 -c 'print(sum([...]))'`，得到 8484。
6. **解法三：Web Search ＝ RAG**：搜尋也是一種工具。計算機幫它算，搜尋幫它查：先查資料，再回答。RAG 分三步：
   - R 檢索：找資料。
   - A 增強：把資料和問題一起交給 AI。
   - G 生成：照資料回答，並附上來源。
   比喻：開書考。
7. **再下一步：Agent**：會自己用工具、執行任務，Codex 就是一個 Agent。

### 50–67　練習 1：和 ChatGPT 聊天

同一個問題問三次，看「給不給資料」差在哪：
- 1-1（幻覺）：先不給資料，問「劉備聽完曹操說『天下英雄只有你我』，做了什麼？為什麼？」它會憑記憶答出掉筷子、怕被看穿。
- 1-2（查證）：追問「你說的原因，原文哪一句寫的？引用原句，附維基文庫連結」，點開連結後按 Cmd/Ctrl+F 搜「掩飾」，搜得到同一句才算數。
- 1-3（RAG）：開新對話，附上第 21 回的一段節錄再問同一題。節錄只寫他吃了一驚、筷子掉了，沒寫原因；看它有沒有照原文說「原文沒寫」，還是又補了原因。補了就追問「原文哪一句？」。
- 提示詞和原文都放在練習資料夾的 `prompts.md`（GitHub 上可直接開），不用照投影片打字。
- 還沒裝好 Codex 的人，這段時間由助教協助安裝。

### 73–90　看懂 Codex CLI

- 啟動畫面：model、directory 兩個欄位。
- 第一次啟動的三個畫面：登入、信任資料夾、寫檔前確認。
- **Session**：一次工作的工作桌，前面講過的它都看得到；`/new` 會換一張空桌子。
- **`/status`**：Model、Directory、Permissions、Session，動手前先看 Directory。
- **Usage 和 Token**（簡單帶過）：Usage 是帳號額度，Token 是處理文字的單位。
- **Memory**：分兩層。聊天裡說的，換了 Session 就忘；寫進 `AGENTS.md` 的，每次開 Session 都會讀。

### 90–112　練習 2：用 Codex 寫大綱

1. 先打 `ls`（Windows 命令提示字元打 `dir`），看到 `原文`、`prompts.md`、`回目.md` 才打開 Codex，再用 `/status` 確認 Directory。只看 Directory 分不出 Windows 解壓縮多包的那一層。
2. 在 `AGENTS.md` 寫規則：「只根據 原文/ 回答，找不到就說『原文/ 裡找不到』，每次回答最後一行寫『出處：原文/第00N回.txt』」。開新 Session 問「劉備第一次出場在第幾回？」，最後一行有這個格式才算生效；再問「諸葛亮第一次出場在第幾回？」，有規則會說找不到，沒有規則會答第 37 回。
3. 請 Codex 根據資料夾裡的回目原文，寫出第 1–21 回的大綱：人名寫成 `[[人名]]`，每段標回目，存成 `三國演義大綱.md`。
4. 核對：請 Codex「大綱第 N 回第二句，根據原文哪一句？引用原句」，再用文字編輯／記事本打開那一回，Cmd/Ctrl+F 搜那句；標題和 `回目.md` 對一對。這一步就是第一次在自己的資料上做 RAG。

**課前準備**：安裝 Node.js 和 Codex、確認 ChatGPT 方案能用 Codex；講師準備練習資料夾（含回目原文）。

## 第二堂：Obsidian 與 RAG（120 分鐘）

| 時間 | 段落 | 內容 |
| --- | --- | --- |
| 00–10 | 回顧 | 上一堂的大綱；今天要把它放進筆記庫 |
| 10–30 | Obsidian 是什麼 | 見下方說明 |
| 30–45 | 練習 1：安裝 | 下載 Obsidian、改繁體中文介面、打開講師的三國筆記庫 |
| 45–70 | 練習 2：把大綱放進筆記庫 | 見下方說明 |
| 70–97 | 在筆記庫裡做 RAG | 見下方說明 |
| 97–115 | 練習 4：建立知識圖譜 | 見下方說明 |
| 115–120 | 收尾 | 預告 Skills；課前作業：終端機打 `git --version` 確認有 git（第三堂安裝 Skill 要用） |

### 10–30　Obsidian 是什麼

- 筆記庫就是電腦裡的一個資料夾，每張卡是一個 `.md` 檔。資料在自己手上，Codex 也讀得到。
- `[[雙向連結]]`：在卡片裡寫 `[[劉備]]` 就連到〈劉備〉；對方的「反向連結」會列出誰提到它。
- 還沒建立的卡，連結的顏色會比較淡。
- 卡片分三種：人物、勢力、關係（事件）。人物靠關係卡連起來。

### 45–70　練習 2：把大綱放進筆記庫

- 把 `三國演義大綱.md` 放進筆記庫的「整理」資料夾。人物卡一律用講師提供的版本，避免同名卡互相蓋掉。
- 點大綱裡的 `[[劉備]]`，確認會跳到講師的人物卡。
- 找出大綱裡顏色比較淡的連結，用 Cmd/Ctrl+Shift+F 搜這個人出現幾次，決定要補卡、還是先留著。
- 自己寫一張關係卡，連到兩位有卡的人物（例如第 20 回許田打圍）。打開〈關羽〉這類人物卡，反向連結出現你的卡就成功。

### 70–97　在筆記庫裡做 RAG（本堂重點）

- 用 Codex 打開筆記庫，問「曹操參與哪場戰役？」，要求回答附上檔名。
- 拆開看 RAG 三步：
  - **R**：它讀了哪幾張卡（看 Codex 列出的檔案）。
  - **A**：它把問題和卡片內容一起帶進回答。
  - **G**：回答附上檔名。
- 比一比：同一題問沒有筆記庫的 ChatGPT，和問有筆記庫的 Codex，差在哪？
- 為什麼連結寫得好，答案就比較好：Agent 會順著連結找到相關的卡。
- RAG 的限制：筆記沒寫的找不到，資料多了也會看漏，所以要核對。
- 練習 3：全班核對同一份講師實跑回答（`examples/aw-02-check/`，對照同一份範例大綱），用三件事核對：檔名真的存在、卡片裡有那句話、它沒有自己補內容。抓到問號就回頭追問 Codex「大綱第 N 回哪一句寫了…？」。有時間再問選做題（例如「白門樓上劉備說了什麼原話？」），這類題目模型記得的比卡片多，看得出它有沒有多寫。

### 97–115　練習 4：建立知識圖譜

- 先看 Obsidian 內建的關係圖（Graph view），包括單張卡的局部關係圖。
- 請 Codex 把〈桃園結義〉〈煮酒論英雄〉相關的人物畫成 ASCII 關係圖，每條線標出來源卡。
- 第 1 輪：全班先核對講師的固定結果（9 條線，有 2 條找不到原句）。第 2 輪：核對自己跑出來的線，找不到原句就回覆 Codex 請它刪掉。
- 把大綱裡還是黑字的事件補成連結，例如練習 2 自己寫的卡。

**課前準備**：講師的三國筆記庫 ZIP；卡片模板加上 `回目`、`年份` 欄位，第三堂做時間軸要用。

### 10–35　什麼是 Skill（本堂重點）

- Skill 是交給 Agent 的一份 SOP：某一類工作要怎麼做、做完長什麼樣子。
- 打開一份 `SKILL.md` 看結構：`name`、`description`（決定什麼時候會被叫出來）、步驟、輸出格式。
- 四種東西的比較：

| | 是什麼 | 什麼時候用 |
| --- | --- | --- |
| Prompt | 這一次的要求 | 只做一次的事 |
| AGENTS.md | 這個專案的規則 | 每次都要遵守的事 |
| Skill | 某一類工作的做法 | 常常重複做的事 |
| MCP | 連到外部工具或資料 | 要查外部系統的時候 |

### 35–50　練習 1：安裝熱門 Skill

- 安裝 diagram-design：
  ```bash
  codex plugin marketplace add cathrynlavery/diagram-design
  codex plugin add diagram-design@diagram-design
  ```
- 安裝 eli5（用白話解釋）：`npx -y skills add dreambigou/eli5 -g -a codex -y`。
- 安裝前先打 `git --version`：兩種安裝方式都會用 git。沒有的話，Mac 打 `xcode-select --install`，Windows 到 git-scm.com 下載。
- 第一次用 diagram-design 會先問要用哪種樣式，回答「保留預設樣式」（選項代號會隨版本變，2.6.115 是 (e)）。
- 開新 Session，確認 Codex 看得到這兩個 Skill。

### 50–70　練習 2：用 Skill 做好讀的筆記

- 用 diagram-design 把一組關係卡畫成 HTML 關係圖，存進筆記庫。
- 用 eli5 把一張人物卡改寫成國中生讀得懂的版本。
- 核對：找出 eli5 多加的比喻或延伸句（它的 SKILL.md 本來就要求打比方），追問「原卡哪一句寫的？」。

### 70–85　練習 3：擴充筆記庫

- 請 Codex 依原文新增三張卡（三英戰呂布、白門樓、草船借箭），套用卡片模板，填好 `回目`、`年份`，每張卡附原文出處。三張都要做，練習 4 的時間軸會用到。
- 核對年份：這三回原文都沒有「初平」「建安」這類年號。年份有填，就到原文 Cmd/Ctrl+F 搜它填的年號，搜不到就刪。
- 這一步用的是 RAG 的規則：只照原文寫，找不到就不寫。
- 先擴充，下一個練習的時間軸才有足夠的資料。

### 85–112　練習 4：寫自己的 Skill

- 題目：`三國時間軸` Skill。讀筆記庫所有卡片的 `回目`、`年份`，依先後排好，產生一張時間軸筆記：卡片裡放一段 HTML，人名用純文字，不用 `[[連結]]`，這樣第四堂可以直接發布。
- 步驟：
  1. 請 Codex 照講師給的骨架建好 `.agents/skills/sanguo-timeline/SKILL.md`（不用自己在 Finder 建隱藏資料夾）。
  2. 開新 Session 執行，看結果。
  3. 說明書沒寫清楚就補一條規則：在結果裡搜 `未標註`、`—`、`<a href`、`[[`，搜到就請 Codex 在 `SKILL.md` 補規則，再跑一次。四個都搜不到，就挑一個自己不滿意的地方寫成規則。重點是學會「改說明書」，不是每次重打提示詞。
- 進階：把 Skill 改成能指定人物，只排出劉備相關的事件。

**課前準備**：通知學生先確認 `git --version`；先在 Codex 實測 diagram-design、eli5 的安裝方式；準備時間軸 Skill 的骨架。

## 第四堂：發布成網站（120 分鐘）

**這堂課結束時，學生會有：** 一個公開網址，同學可以從首頁一路點進每張卡。

| 時間 | 段落 | 內容 |

| 90–105 | 練習 4：互相驗收 | 公開〈三英戰呂布〉並加進導覽頁；從 Vercel 專案 Domains 複製最短的網址，先用自己的無痕視窗走一次，再請同學從首頁走到它 |
| 105–120 | 總結與延伸 | 見下方說明 |

### 10–30　筆記怎麼變成網址

- 流程：筆記 → GitHub 儲存庫 → Vercel 自動建置 → 網址。
- CI/CD 的概念：每次推上 GitHub，網站就自動重建，不用手動上傳。
- 公開範圍：只有勾了 `dg-publish` 的卡會上網站，其他的留在自己電腦。

### 105–120　總結與延伸

- Git 基礎：`commit` 和 `push`，進階的人可以改用 GitHub Actions 部署。
- 四堂課回顧：大綱 → 筆記庫 → 時間軸 → 網站。
- 課後延伸：llm-wiki 這類筆記庫 Skill。

**課前準備**：學生先註冊 GitHub 和 Vercel，避免現場一起註冊卡在 email 驗證；並確認打得開 github.com/settings/personal-access-tokens/new（GitHub 會要求再輸入密碼或驗證碼，新帳號可能要求設定 2FA）。第三堂缺課或沒做完的人，用 `examples/aw-04-lab/第三堂完成版.zip` 補上。

## 實測結果（2026-10-17，講師電腦，Codex 0.154.0）

1. **第一堂的大綱資料**：已經準備好 `examples/aw-01-lab/`，也打包成 `examples/aw-01-lab.zip`（投影片 QR 指向 GitHub raw 連結，要 push 到 main 才能下載）。裡面有維基文庫第 1–21 回的全文（`原文/第001回.txt`…`第021回.txt`）、`回目.md` 和 `prompts.md`。用練習 2-3 的提示詞實跑：1 分 38 秒寫完 21 段，每段都附出處。有一個小毛病：它把回目標題裡的人名也加上了 `[[ ]]`。提示詞要補一句「標題裡的人名不用加連結」。
2. **HTML 能不能上 Digital Garden**：用講師網站的模板在本機建置測試。
   - 筆記裡直接寫 HTML、`<style>`、`<script>`，都能正常顯示、執行。
   - **HTML 區塊裡的 `[[連結]]` 不會轉成連結**，會原封不動顯示出來。時間軸 Skill 產出的 HTML 要用純文字人名，或改用一般的 `<a href>`。
   - 獨立的 `.html` 檔，Obsidian 外掛不會上傳。要放進網站 repo 的 `extra/` 資料夾，再用 `<iframe>` 嵌進筆記。注意：講師網站能這樣做，是因為 `.eleventy.js` 加過 `eleventyConfig.addPassthroughCopy({ "extra": "extra" });`。新開的 Digital Garden 模板沒有這一行，要自己加。
   - 還沒透過 Obsidian 外掛實際發布到線上驗證。
3. **沒有 Codex 方案的學生**（2026-10-17 實測），建議的順序：
   - **第一順位：opencode＋免費雲端模型**。不用登入，也不用信用卡。
     1. 用 `npm install -g opencode-ai` 安裝（opencode 1.19.3）。
     2. 在資料夾裡打 `opencode`。
     3. 用 `/models` 選 DeepSeek V4.1 Flash Free 或 GLM-5.3 Flash Free。
     - 實測：列檔加建檔 29 秒成功；照第 1 回原文寫大綱，15 秒，內容正確。
     - opencode 會讀 AGENTS.md，沒有 `/status`。
     - 速率限制官方沒寫，超過會回 429。全班用同一個 IP 可能被限流，免費模型清單也會變。
     - 不要放個資。Big Pickle 等模型可能拿資料訓練。
   - **第二順位：Codex＋OpenRouter**：
     1. 註冊 OpenRouter，拿 API key。
     2. 在 config 寫 `[model_providers.openrouter]`，`wire_api = "responses"`。
     - 免費額度每天 50 次。設定檔語法已驗證，還沒用真 key 跑完整流程。
   - **只當示範：在自己電腦用 Ollama 跑模型**：
     - **1B、2B 不夠用**。llama3.2:1b 不會呼叫工具；qwen3:1.7b 會亂編（「劉備，字孔明」、[[李四]]）；qwen3:4b 很慢，還編出《紅樓夢》人物。
     - 最少要 gemma4:e2b（下載約 4.6 GB，32k context 下吃約 7 GB 記憶體），也只能做「列檔、讀檔、建檔」的示範，寫大綱就不可靠。
     - 8 GB 記憶體的電腦不建議跑；16 GB 可以示範。
     - Context length 一定要調到 32k 以上，預設的 4k 會默默截掉提示詞。
     - 步驟：
       1. `ollama pull gemma4:e2b`
       2. `ollama launch opencode --model gemma4:e2b`（不用寫設定檔）
4. **Skill 安裝**（用三國範例實測）：
   - diagram-design 是 Codex 外掛：`codex plugin marketplace add cathrynlavery/diagram-design`，再 `codex plugin add diagram-design@diagram-design`，兩行都成功。
