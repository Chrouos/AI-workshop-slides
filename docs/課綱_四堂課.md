# AI 協作工作坊課綱：用 AI 建一座三國知識庫

四堂課，每堂 2 小時（含練習），共 8 小時。

整個課程只做一件作品：一座《三國演義》知識庫。第一堂用 Codex 寫出大綱，第二堂放進 Obsidian 和人物卡連起來，第三堂用 Skill 擴充、畫圖、排時間軸，第四堂發布成網站。每堂課都接著上一堂的成果做。

三條主線貫穿四堂課：

| 主線 | 第一堂 | 第二堂 | 第三堂 | 第四堂 |
| --- | --- | --- | --- | --- |
| RAG | 概念：Web Search 就是 RAG | 實作：在自己的筆記庫查資料、附出處 | 應用：照原文新增卡片 | 成果：網站上每張卡都有出處 |
| Obsidian | （預告） | 安裝、連結、關係圖 | 卡片模板、時間欄位 | Digital Garden 發布 |
| Skills | （預告：AGENTS.md） | （預告） | 安裝、使用、自己寫一個 | 把 Skill 產出放上網站 |

## 第一堂：認識 AI，學會用 Codex（120 分鐘）

**這堂課結束時，學生會有：** 一份 `三國演義大綱.md`，人名都寫成 `[[劉備]]` 這種連結，每段標上回目。

| 時間 | 段落 | 內容 |
| --- | --- | --- |
| 00–10 | 開場 | 自我介紹；四堂課的作品地圖（大綱 → 筆記庫 → 時間軸 → 網站） |
| 10–40 | GPT 怎麼走到今天 | 見下方說明 |
| 40–50 | ChatGPT 和 Codex 差在哪 | ChatGPT 在對話框裡聊；Codex 在你的資料夾裡讀檔、改檔、存檔 |
| 50–67 | 練習 1：和 ChatGPT 聊天 | 見下方說明 |
| 67–73 | 安裝 Codex | Node.js LTS → `npm install -g @openai/codex@latest` → `codex` → 第一次開啟的三個畫面；課前沒裝好的人，助教在練習 1 時協助 |
| 73–90 | 看懂 Codex CLI | 見下方說明 |
| 90–112 | 練習 2：用 Codex 寫大綱 | 見下方說明 |
| 112–120 | 收尾 | 回顧；第二堂前請先下載 Obsidian |

### 10–40　GPT 怎麼走到今天

用一條因果鏈講，每一步都是上一步的問題催生出來的：

1. **預測下一個字（2022，GPT-3.5）**：看前文，從機率表挑下一個字，一直接下去。
2. **隨機性**：每次不一定挑機率最高的那個字，所以同一題問兩次，答案會不一樣。現場示範：同一題按兩次「重新產生」。
3. **幻覺**：它挑的是「最常見的說法」，不是「查證過的說法」，所以會很肯定地講出沒有根據的內容。例子：早期 GPT-3.5 把一長串加法算成 8402（正解 8484）。
4. **解法一：Thinking**：先把問題拆成步驟，一步一步算，再驗算（Chain of Thought）。能減少推理出錯，但它還是只靠自己記得的東西。
5. **解法二：Web Search ＝ RAG**：先查資料，再回答。講 RAG 三步：R 檢索（找資料）、A 增強（把資料和問題一起交給 AI）、G 生成（照資料回答、附來源）。比喻：開書考。
6. **再下一步：Agent**：會自己用工具、執行任務，Codex 就是一個 Agent。

### 50–67　練習 1：和 ChatGPT 聊天

- 不開搜尋，請 ChatGPT 逐字引用《三國演義》第 21 回曹操說「天下英雄」那一句，再到維基文庫比對。
- 同一題打開搜尋再問一次，看回答有沒有附來源，點開來源核對。
- 還沒裝好 Codex 的人，這段時間由助教協助安裝。

### 73–90　看懂 Codex CLI

- 啟動畫面：model、directory 兩個欄位。
- 第一次啟動的三個畫面：登入、信任資料夾、寫檔前確認。
- **Session**：一次工作的工作桌，前面講過的它都看得到；`/new` 會換一張空桌子。
- **`/status`**：Model、Directory、Permissions、Session，動手前先看 Directory。
- **Usage 和 Token**（簡單帶過）：Usage 是帳號額度，Token 是處理文字的單位。
- **Memory**：分兩層。聊天裡說的，換了 Session 就忘；寫進 `AGENTS.md` 的，每次開 Session 都會讀。

### 90–112　練習 2：用 Codex 寫大綱

1. 在練習資料夾打開 Codex，用 `/status` 確認 Directory。
2. 在 `AGENTS.md` 寫一條規則，例如「只根據資料夾裡的原文回答，找不到就說找不到」，再開新 Session 驗證它記得。
3. 請 Codex 根據資料夾裡的回目原文，寫出第 1–21 回的大綱：人名寫成 `[[人名]]`，每段標回目，存成 `三國演義大綱.md`。
4. 抽兩段回原文核對。這一步就是第一次在自己的資料上做 RAG。

**課前準備**：安裝 Node.js 和 Codex、確認 ChatGPT 方案能用 Codex；講師準備練習資料夾（含回目原文）。

## 第二堂：Obsidian 與 RAG（120 分鐘）

**這堂課結束時，學生會有：** 一座連好的三國筆記庫（自己的大綱＋講師的人物、勢力、關係卡），和一張自己畫的關係圖。

| 時間 | 段落 | 內容 |
| --- | --- | --- |
| 00–10 | 回顧 | 上一堂的大綱；今天要把它放進筆記庫 |
| 10–30 | Obsidian 是什麼 | 見下方說明 |
| 30–45 | 練習 1：安裝 | 下載 Obsidian、改繁體中文介面、打開講師的三國筆記庫 |
| 45–70 | 練習 2：把大綱放進筆記庫 | 見下方說明 |
| 70–95 | 在筆記庫裡做 RAG | 見下方說明 |
| 95–115 | 練習 4：建立知識圖譜 | 見下方說明 |
| 115–120 | 收尾 | 預告 Skills |

### 10–30　Obsidian 是什麼

- 筆記庫就是電腦裡的一個資料夾，每張卡是一個 `.md` 檔。資料在自己手上，Codex 也讀得到。
- `[[雙向連結]]`：在卡片裡寫 `[[劉備]]` 就連到〈劉備〉；對方的「反向連結」會列出誰提到它。
- 還沒建立的卡，連結的顏色會比較淡。
- 卡片分三種：人物、勢力、關係（事件）。人物靠關係卡連起來。

### 45–70　練習 2：把大綱放進筆記庫

- 把 `三國演義大綱.md` 放進筆記庫的「整理」資料夾。人物卡一律用講師提供的版本，避免同名卡互相蓋掉。
- 點大綱裡的 `[[劉備]]`，確認會跳到講師的人物卡。
- 找出大綱裡顏色比較淡的連結，決定要補卡、還是改成已有的卡名。
- 自己寫一張關係卡，連到兩位人物。

### 70–95　在筆記庫裡做 RAG（本堂重點）

- 用 Codex 打開筆記庫，問「曹操參與哪場戰役？」，要求回答附上檔名。
- 拆開看 RAG 三步：
  - **R**：它讀了哪幾張卡（看 Codex 列出的檔案）。
  - **A**：它把問題和卡片內容一起帶進回答。
  - **G**：回答附上檔名。
- 比一比：同一題問沒有筆記庫的 ChatGPT，和問有筆記庫的 Codex，差在哪？
- 為什麼連結寫得好，答案就比較好：Agent 會順著連結找到相關的卡。
- RAG 的限制：筆記沒寫的找不到，資料多了也會看漏，所以要核對。
- 練習 3：每人問一題，用三件事核對回答：檔名真的存在、卡片裡有那句話、它沒有自己補內容。

### 95–115　練習 4：建立知識圖譜

- 先看 Obsidian 內建的關係圖（Graph view），包括單張卡的局部關係圖。
- 請 Codex 把〈桃園結義〉〈煮酒論英雄〉相關的人物畫成 ASCII 關係圖，每條線標出來源卡。
- 對照卡片，刪掉沒有原句支持的線；把發現漏掉的連結補回卡片裡。

**課前準備**：講師的三國筆記庫 ZIP；卡片模板加上 `回目`、`年份` 欄位，第三堂做時間軸要用。

## 第三堂：Skills（120 分鐘）

**這堂課結束時，學生會有：** 一份自己寫的時間軸 Skill，和一頁由它產生的三國時間軸 HTML。

| 時間 | 段落 | 內容 |
| --- | --- | --- |
| 00–10 | 回顧 | 上一堂的筆記庫和關係圖 |
| 10–35 | 什麼是 Skill | 見下方說明 |
| 35–50 | 練習 1：安裝熱門 Skill | 見下方說明 |
| 50–70 | 練習 2：用 Skill 做好讀的筆記 | 見下方說明 |
| 70–85 | 練習 3：擴充筆記庫 | 見下方說明 |
| 85–112 | 練習 4：寫自己的 Skill | 見下方說明 |
| 112–120 | 收尾 | 第四堂前請先註冊 GitHub、Vercel |

### 10–35　什麼是 Skill（本堂重點）

- Skill 是交給 Agent 的一份 SOP：某一類工作要怎麼做、做完長什麼樣子。
- 打開一份 `SKILL.md` 看結構：`name`、`description`（決定什麼時候會被叫出來）、步驟、輸出格式。
- 四種東西的比較：

| | 是什麼 | 什麼時候用 |
| --- | --- | --- |
| Prompt | 這一次的要求 | 只做一次的事 |
| AGENTS.md | 這個專案的規則 | 每次都要遵守的事 |
| Skill | 某一類工作的做法 | 常常重複做的事 |
| MCP | 連到外部工具或資料 | 要查外部系統的時候 |

### 35–50　練習 1：安裝熱門 Skill

- 安裝 diagram-design：
  ```bash
  codex plugin marketplace add cathrynlavery/diagram-design
  codex plugin add diagram-design@diagram-design
  ```
- 安裝 eli5（用白話解釋）：`npx -y skills add dreambigou/eli5 -g -a codex -y`。
- 第一次用 diagram-design 會先問要用哪種樣式，回答「1」。
- 開新 Session，確認 Codex 看得到這兩個 Skill。

### 50–70　練習 2：用 Skill 做好讀的筆記

- 用 diagram-design 把一組關係卡畫成 HTML 關係圖，存進筆記庫。
- 用 eli5 把一張人物卡改寫成國中生讀得懂的版本。
- 核對：圖上的每條線、改寫後的每件事，在原卡都找得到。

### 70–85　練習 3：擴充筆記庫

- 請 Codex 依原文新增幾張卡（例如官渡之戰、赤壁之戰），套用卡片模板，填好 `回目`、`年份`，每張卡附原文出處。
- 這一步用的是 RAG 的規則：只照原文寫，找不到就不寫。
- 先擴充，下一個練習的時間軸才有足夠的資料。

### 85–112　練習 4：寫自己的 Skill

- 題目：`三國時間軸` Skill。讀筆記庫所有卡片的 `回目`、`年份`，依先後排好，產生一張時間軸筆記：卡片裡放一段 HTML，人名用純文字，不用 `[[連結]]`，這樣第四堂可以直接發布。
- 步驟：
  1. 講師給 `SKILL.md` 骨架，學生填 description 和步驟。
  2. 開新 Session 執行，看結果。
  3. 不滿意就改 `SKILL.md`，再跑一次。重點是學會「改說明書」，不是每次重打提示詞。
- 進階：把 Skill 改成能指定人物，只排出劉備相關的事件。

**課前準備**：先在 Codex 實測 diagram-design、eli5 的安裝方式；準備時間軸 Skill 的骨架。

## 第四堂：發布成網站（120 分鐘）

**這堂課結束時，學生會有：** 一個公開網址，同學可以從首頁一路點進每張卡。

| 時間 | 段落 | 內容 |
| --- | --- | --- |
| 00–10 | 回顧 | 先看一個做好的範例網站 |
| 10–30 | 筆記怎麼變成網址 | 見下方說明 |
| 30–55 | 練習 1：建立網站 | 用 Digital Garden 模板，從 GitHub 部署到 Vercel |
| 55–75 | 練習 2：連接 Obsidian | 安裝 Digital Garden 外掛、建立 GitHub token、填進外掛 |
| 75–90 | 練習 3：挑卡發布 | 勾選 `dg-publish` 的卡才會公開；做一張導覽首頁；發布 |
| 90–105 | 練習 4：互相驗收 | 公開一張新卡，請同學從首頁走到它 |
| 105–120 | 總結與延伸 | 見下方說明 |

### 10–30　筆記怎麼變成網址

- 流程：筆記 → GitHub 儲存庫 → Vercel 自動建置 → 網址。
- CI/CD 的概念：每次推上 GitHub，網站就自動重建，不用手動上傳。
- 公開範圍：只有勾了 `dg-publish` 的卡會上網站，其他的留在自己電腦。

### 105–120　總結與延伸

- Git 基礎：`commit` 和 `push`，進階的人可以改用 GitHub Actions 部署。
- 四堂課回顧：大綱 → 筆記庫 → 時間軸 → 網站。
- 課後延伸：llm-wiki 這類筆記庫 Skill。

**課前準備**：學生先註冊 GitHub 和 Vercel，避免現場一起註冊卡在 email 驗證。

## 實測結果（2026-10-17，講師電腦，Codex 0.154.0）

1. **第一堂的大綱資料**：已經準備好 `examples/aw-01-lab/`，也打包成 `examples/aw-01-lab.zip`（投影片 QR 指向 GitHub raw 連結，要 push 到 main 才能下載）。裡面有維基文庫第 1–21 回的全文（`原文/第001回.txt`…`第021回.txt`）、`回目.md` 和 `prompts.md`。用練習 2-3 的提示詞實跑：1 分 38 秒寫完 21 段，每段都附出處。有一個小毛病：它把回目標題裡的人名也加上了 `[[ ]]`。提示詞要補一句「標題裡的人名不用加連結」。
2. **HTML 能不能上 Digital Garden**：用講師網站的模板在本機建置測試。
   - 筆記裡直接寫 HTML、`<style>`、`<script>`，都能正常顯示、執行。
   - **HTML 區塊裡的 `[[連結]]` 不會轉成連結**，會原封不動顯示出來。時間軸 Skill 產出的 HTML 要用純文字人名，或改用一般的 `<a href>`。
   - 獨立的 `.html` 檔，Obsidian 外掛不會上傳。要放進網站 repo 的 `extra/` 資料夾，再用 `<iframe>` 嵌進筆記。注意：講師網站能這樣做，是因為 `.eleventy.js` 加過 `eleventyConfig.addPassthroughCopy({ "extra": "extra" });`。新開的 Digital Garden 模板沒有這一行，要自己加。
   - 還沒透過 Obsidian 外掛實際發布到線上驗證。
3. **沒有 Codex 方案的學生**：照樣用 Codex CLI，只是在 `~/.codex/config.toml` 換掉模型來源（Windows 在 `%USERPROFILE%\.codex\config.toml`）。不要用 `codex --oss`：沒登入的電腦還是會先跳 ChatGPT 登入畫面，而且會自動下載約 14 GB 的模型。
   - **Ollama（本機，免費，電腦要夠力）**：
     1. 安裝 Ollama。
     2. **把 Context length 調到 64k**。預設的 4k 會把 Codex 的指令截掉，模型只會回「無法存取檔案」，也不報錯。
     3. `ollama pull gpt-oss:20b`（約 14 GB，建議記憶體 16 GB 以上）。
     4. 在 config 寫 `model_provider = "ollama"`、`model = "gpt-oss:20b"`。
     5. 打 `codex`。
     - 本機實測：32k context 下，小模型也能列檔、建檔，約 12 秒。
   - **OpenRouter（雲端免費模型）**：
     1. 註冊、建立 API key。
     2. 設定環境變數 `OPENROUTER_API_KEY`。
     3. 在 config 加上 `[model_providers.openrouter]`，`base_url = "https://openrouter.ai/api/v1"`，**`wire_api` 一定要是 `"responses"`**（0.154 已經不支援 `"chat"`）。模型例如 `poolside/laguna-xs-2.1:free`。
     - 額度：每天 50 次請求，帳號儲值滿 10 美元才變 1000 次。每一次工具呼叫都算一次，只夠做幾個小任務。
     - 免費模型可能會保留或拿你的提示詞訓練，不要貼私人資料。
     - 免費模型清單變動很快，上課前一天要再查一次。
     - 設定檔語法已驗證，但還沒用真的 key 跑完整流程。
   - 兩條路都比較慢，用工具的能力也比較弱。練習要縮小成列檔、讀檔、建一個檔這種程度。
4. **Skill 安裝**（用三國範例實測）：
   - diagram-design 是 Codex 外掛：`codex plugin marketplace add cathrynlavery/diagram-design`，再 `codex plugin add diagram-design@diagram-design`，兩行都成功。
   - eli5 是一般 Skill，不是外掛，用外掛指令裝會失敗。改用 `npx -y skills add dreambigou/eli5 -g -a codex -y`，會裝到 `~/.agents/skills/eli5`，Codex 看得到。
   - **第一次用 diagram-design，它會先停下來問要用哪種樣式**，學生要回「1」（預設樣式）。這一步要寫進投影片。
   - diagram-design 畫出的關係圖，線上的標籤會疊在一起，要再請它把標籤分開。這可以當成教學點：第一次畫出來不完美，要再調整。
   - eli5 改寫的劉備卡內容正確，但它把 `dg-publish: true` 也一起抄過去了。第四堂發布前要提醒學生檢查。

5. **第三堂實跑**（在範例筆記庫的副本上跑）：
   - **新增卡片**：照原文新增三英戰呂布、白門樓、草船借箭三張卡。Codex 會先整理計畫，問「請回覆『可以』」，等你同意才寫檔。年份照規則留空，只有已經有卡的人名加上連結。
   - **專案 Skill**：`sanguo-timeline` 放在筆記庫的 `.agents/skills/` 裡，Codex 讀得到，不一定要裝到全域。
   - **時間軸**：排出 6 件事，第 1 到 49 回。實跑出兩個可以拿來教的錯誤：
     - 年份欄寫成「未標註」，Skill 要的是留空。
     - 「來源卡」連到 `../關係/*.md`，在網站上會 404。
     兩個錯都是在 SKILL.md 多寫一行就能修好。
   - **時間軸筆記沒有 frontmatter**：發布前要自己加上 `dg-publish: true`。
